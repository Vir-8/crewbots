Propose approved work for merging. Every review of its current version must have passed. The user merges, or crewbots merges approved work when the user has turned that on. The merge is local only; the user pushes and deploys. Work done in a project's folder itself is committed there instead: just the files it handed back as its output, on the folder's branch. Uncommitted worktree changes are committed as part of the merge. If an automatic merge fails, the proposal waits for the user and the reason is returned. summary: what changed and how it was verified; its first line is the commit's subject, so make it say plainly what the change does ("Add greet() with its test"), as a commit subject would.
